# 功能边界与接入职责

[English](method.en.md) | [简体中文](method.md) · [首页](README.zh-CN.md) · [使用指南](usage.md)

## 判断和执行分开

输入原始任务 task 与当前 messages，输出当前时机的压缩、召回建议。两项判断独立，可能同时为“是”，也可能同时为“否”。

| 环节 | TierSense-Memory-Decide | 接入方 Agent |
| --- | --- | --- |
| 获取原始任务 | 接收 task，兼容支持的任务提取 | 首轮保存用户问题并传入 |
| 当前上下文 | 接收消息及已完成工具结果 | 提供真实、完整、有序历史 |
| 是否压缩／召回 | 返回 predicted 与 confidence | 检查历史／记忆是否实际存在 |
| 历史选择与摘要 | 不执行、不返回索引 | 选择完整历史块并生成摘要 |
| 记忆检索与注入 | 不执行、不返回检索文本 | 保存、检索、去重并注入相关信息 |
| 继续任务 | 不调用主 Agent 模型 | 将真实更新后的上下文交给主模型 |

## 与 TierSense-Compress 的区别

[TierSense-Compress](../../docs/compress/README.zh-CN.md) 提供逐历史步骤的压缩建议与片段定位；本项目提供当前时机的压缩／召回双判断。不要将另一个接口的 options、steps 或 execution.spans 当成本接口的能力。

## 接入原则

- 在工具结果全部返回后调用，不拆散调用与结果。
- 明确传入 task，避免中途接入时原始问题丢失。
- 先判断业务前提，再执行建议；没有历史或记忆则跳过对应动作。
- 执行成功后才提交上下文变更；执行失败保留原上下文。
- confidence 表示对当前判断的支持程度，不是任务成功率。
- 各 Agent 示例仅描述支持的消息格式，不代表所有版本均已做完整闭环验收。

本页只说明公开产品行为与接入职责，不披露内部训练与推理实现。
