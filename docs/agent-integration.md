# Agent 组合接入

[English](agent-integration.en.md) · [首页](../README.zh-CN.md)

## 独立接入优先

三个模块不是强制串联链路。按目标选择一个模块即可；主 Agent、摘要模型和记忆存储仍由你的应用负责。保存原始 task，并在支持的接口中随真实 messages 传入，避免原始问题在长历史中丢失。

## 可选组合

```text
本轮工具结果全部返回
        ↓
当前完整上下文 + 原始 task
        ↓
Memory-Decide：现在是否需要压缩／召回？（可选）
        ├─ 压缩建议 → Compress 选择候选历史 → 应用摘要与更新
        └─ 召回建议 → 应用检索已保存记忆 → 去重与注入
        ↓
Score：对准备交给主模型的上下文评分（可选）
        ↓
应用路由策略选择模型 → 主 Agent 继续任务
```

这是组合接入建议，不代表该组合已完成统一端到端评测，也不承诺比单模块更好或更省钱。不要为了使用全套产品而在每轮调用所有接口。

## 应用需要保证

- 等待全部工具结果返回，保留调用与结果的完整配对。
- 压缩和召回分别检查是否有可操作的数据；模型建议不代替业务前提。
- Memory-Decide 的压缩建议不保证 Compress 一定选中片段；没有候选则保留历史。
- 先保存可追溯原文，再按业务策略生成摘要；摘要成功后才提交替换。
- 召回内容由应用去重，避免重复注入；两项都为是时由应用安排执行顺序。
- Score 只提供分数，阈值和模型映射由应用定义。
- 调用或执行失败时保留原上下文并记录失败，不伪造成功或负向建议。
- 不把一种接口的置信度或执行参数直接套用到另一接口。

现有 API 地址、Key 使用方式和返回格式不因本总入口而改变。没有新增统一 API 或自动执行插件。
